# 小米笔记思维笔记真机对照：拾页 Native 改版规格

2026-11-12 在 Xiaomi 17 Pro Max（小米笔记 3.2.7.9，1200 × 2608，480 dpi）上，以新建的测试笔记观察创建、输入、新增分支、调整层级、折叠和列表／思维树切换；随后对照同一设备上拾页 Native 0.1.0 和 Android 源码。测试笔记已删除。未操作正在使用的 Xiaomi 17，也未用已有笔记做交互或记录其内容。

## 真机交互链

| 场景 | 小米笔记的实际行为 | 对 Native 的要求 |
| --- | --- | --- |
| 开始 | 普通空白笔记的正文起始处提供“创建思维笔记”。触发后直接显示居中的中心主题，不先展示空列表。 | 保留 Native 首页独立“灵感笔记”入口，但打开后默认显示中心主题，并允许在普通空白笔记里原地转换。 |
| 标题 | 中心主题就是笔记名称。列表视图把它放在正文顶部，字号和字重明显高于分支，下方是淡色日期与字数；树视图只显示中心节点。 | `note.title` 与根节点文字是同一份内容；树模式不要在顶栏再显示一遍标题。 |
| 树中选中 | 点中心节点直接进入就地文字编辑并唤起键盘；选中节点旁出现圆形新增入口和小型编辑标识。输入时画布平移，当前节点保持可见。 | 单击节点就地编辑。新增入口贴近选中节点；编辑动作不能依赖双击和底部弹窗。 |
| 树中结构 | 中心节点为实心暖色圆角矩形，子节点为浅色；细线直接连接父子，节点之间留大量空白。非编辑状态只保留顶部返回、模式切换和选项。 | 使用拾页品牌绿色建立同样的主次层级、留白和细连接线；结构按钮随选中节点出现。 |
| 列表输入 | 点分支文字后光标就地出现；在光标处回车把当前文字拆成两个同级节点，而非简单在末尾追加。 | 以光标位置拆分文字，原节点保留前半段，新同级节点接收后半段并获得焦点。 |
| 改层级 | 键盘上方只出现升级、降级两个圆形按钮；不可操作的一侧置灰。降级把当前节点及后代移到前一同级节点下面。 | 两个动作贴近输入区，按当前节点计算可用状态；整支移动，保留焦点与光标。 |
| 层级显示 | 叶节点用小圆点；有子节点的节点用朝下三角，并沿子树显示细竖线。点三角收起子树，图标朝右。 | 列表必须显示完整层级结构、折叠控制与竖向引导线，避免单纯文字缩进。 |
| 折叠跨视图 | 列表中收起分支后切到树，子树仍被收起，节点旁有隐藏数量徽标。切回来仍保持折叠。 | 折叠状态属于笔记的视图状态，在两种呈现里一致；节点数据不得因折叠丢失。 |
| 切换视图 | 顶部两个互斥图标往返切换；视图有连续的转场，当前结构和文字即时对应，且不出现重复标题。 | 同一份节点树驱动两种视图，切换时保留选中节点和视口锚点；内容在动画过程中就位。 |
| 选项 | 树视图右上角使用紧凑的圆角悬浮菜单，包含保存为图片、移动、分享、删除等；不占据整屏底部。 | 笔记级动作放顶栏气泡菜单；节点级动作靠近节点或输入区。 |

这些观察描述的是这台手机当前版本的实际行为，不把小米的颜色、图标或具体动效时长当作要复制的资产。尚未确认长按拖动排序、实体键盘快捷键及多行节点的边界行为。

## Native 当前差距与原因

1. `MindMapPanel.kt` 默认 `treeMode = false`，新建后先出现空列表和“点击下方子主题”的说明；而小米直接从中心主题开始。`MainActivity.kt` 在新建时进入编辑态，底部五个文字按钮立即占满宽度。
2. `MainActivity.kt` 始终在顶栏展示 `note.title`，树上又绘制根节点文字，形成重复标题；根节点经树内弹窗编辑时，`MindMapPanel.save()` 没有把新文字同步回 `note.title`，存在标题与中心主题分叉的风险。
3. 列表节点只有单行 `EditText` 和缩进，没有圆点、折叠三角、引导线及子树收起。回车一律在当前节点后插入“新分支”，不按光标拆分文本。
4. 树节点必须再次快速点击才走 `editNode()`，随后打开“编辑分支”底部弹窗；小米一次点击直接就地编辑。当前树无贴近节点的加号、上下文控制，也没有选择节点后的视口定位。
5. `MindTreeView.onDraw()` 使用固定 185 × 58 的节点矩形并截断为前 12 个字，文字不能随内容换行；布局从固定偏移起步，画布没有按内容和屏幕尺寸居中。连接线和选中框视觉权重接近，削弱主题层级。
6. `toggleMode()` 通过 `GONE` 和整体淡入切换，不保留同一节点的空间锚点。列表选中节点与树内部选中状态分离。卡片预览只拼接前三个一级分支，无法反映实际层级和折叠后的视觉结构。
7. 每次结构操作调用 `renderList()` 重建所有输入框；每次字符变化都序列化整棵树并使树画布失效。这两点需要在优化时避免输入法焦点跳动和大分支笔记卡顿。

## 改版顺序

1. **统一文档状态。** 以根节点作为标题唯一来源，节点 ID、父子关系、顺序、折叠状态和选中 ID 独立保存；现有 JSON 逐步升级，已有笔记内容不丢失。
2. **先重做列表编辑。** 使用真实的层级列表行、圆点／三角／竖线；回车按光标拆分；升级降级只在键盘上方显示；结构变更局部更新行并保持输入焦点。
3. **再重做树编辑。** 测量文字后决定节点宽高，绘制细连接线；新建时中心主题居中，选中时就地编辑和新增；平移／缩放只作用于画布内容。
4. **最后做跨视图衔接。** 列表和树以同一选中节点为转场锚点，折叠状态一致；顶部按钮和气泡菜单只承担视图级、笔记级动作；首页卡片预览与真实节点结构一致。

完成标准：在新建笔记中连续输入中心主题、两个同级分支、把第二个降为第一个的子节点、收起第一个、切到树再切回列表，文字、层级、折叠和当前焦点均保持；长节点不截断；键盘升降与节点编辑不闪烁；30 个以上分支仍可即时输入和调整层级。

## 源码复核与本轮进展

另对照 `D:/code/Note/小米笔记-架构与功能实现导览.md` 及解包源码中的 `PhoneWebMindNoteFragment`、`PadWebMindNoteFragment`、`MindNoteWebView`。小米将思维笔记的编辑、增子级、增同级和视图切换通过原生壳与 Web 编辑器协作完成；拾页 Native 继续以原生组件绘制和编辑，只借鉴操作路径，不复用其代码或素材。

本轮已统一根节点与笔记名称，默认打开树视图，补齐树上就地编辑、选中节点的新增入口和自动移入可视区；列表可折叠层级、按光标拆分节点，并用四个直接操作按钮调整结构。Android 与 HarmonyOS 均已原生构建并在真机上核对输入、切换和保存。HarmonyOS 的列表组件复用导致拆分后文字暂留旧值，已通过结构变更时重建节点解决；Android 删除当前笔记后再次保存的缺陷也已修复。

仍需专项处理多行长节点的完整显示、跨视图以节点为锚点的空间转场，以及大规模节点下的输入耗时。上面的完成标准因此保留为后续验收项。
